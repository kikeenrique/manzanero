# Feature status

For one table of what works on which platform, read [status at a glance](status.md) first. This page is the compact inventory of what is available now and how far each area has been checked. “Verified” always means a scoped live result on the recorded device and environment; it is not a general reliability guarantee. [Verification](verification.md) holds the evidence and the failures, the [roadmap](roadmap.md) orders the remaining work, and the [live check plan](live-check-plan.md) lists the hardware runs still owed.

Unless a row says otherwise, physical evidence comes from one iPhone 13 mini (iOS 27.2.1) and simulator evidence from iOS 27.2 runtime simulators.

The tool runs on an Apple silicon Mac with macOS 26.6 or later and Xcode 27 or later. The current beta, v0.1.0-beta.2, was published on 2026-11-21 and installs with `brew install kikeenrique/tap/manzanero`; it has been installed on the development Mac only ([record](verification.md#second-beta-published)).

## Unavailable or missing

- Simulator `wake`: refused as not implemented (`unsupported-operation`). Simulator `paste` is refused because `simctl pbcopy` did not reach the pasteboard. `type` of text the named layout cannot produce is refused in favour of `set-value`, on both platforms.
- Physical `logs` ([app logs](app-logs.md#physical-devices)): a stream from now, at most 600 seconds, of one process until it ends, a group or every process; the device's stored log is not read. It is the only way to debug-level lines from a phone: `console` mirrors info and above. Built on 2026-11-20 and checked on the iPhone 13 mini the same evening; not run on the Apple TV.
- `tree` and the selector commands on a phone in landscape: refused until 2026-11-21; accepted since, with hit points mapped to the display's native portrait, unit-tested only ([accessibility](direct-accessibility.md#current-native-tree-route)).
- `hid-info`, live raw `ax-snapshot`, independent Wi-Fi pairing (`pair wifi`) and `--pairing-file` are no longer commands. Pair through Xcode/CoreDevice; offline `decode-ax-archive` still works.
- One tree for a browser and its page: with a web page in front the tree is the page alone. The browser's own controls are reached by giving the browser's PID to a selector action, which is built and unit-tested but has not run on a device ([web content](direct-accessibility.md#web-content)). Reading, `wait`, `press` and typing work on a page in Chrome on the one phone; `set-value` does not change a web input.
- Elements with neither label nor identifier, such as the Settings search field, are selected by their current value with `--with-value`, run on a simulator only; an element with no value either cannot be selected. One of several elements that share a label, which is common on web pages, is chosen with `--index` ([guide](direct-accessibility.md#current-guarded-native-press)).
- [Device settings](device-settings.md) (`rotate`, `settings` for appearance, text size, contrast and reduced motion, `location`, `status-bar`) and reading the clipboard (`clipboard`) were added on 2026-11-21, through devicectl, and run on an iPhone simulator only.
- `double-tap` was added on 2026-11-21 as a preset over `gesture` (simulator-checked). System gestures (Home, the Centres, back) are not: on a simulator such touch sequences reach the app, not the system ([presets](gesture-sequences.md#presets)).
- A permission prompt is answered with `press --label '^Allow' --match regex` ([recipe](direct-accessibility.md#current-native-tree-route)); there is no separate command, by choice. `create-simulator` makes a simulator of a named type and runtime. They are listed as [commands to add](roadmap.md#commands-to-add).

Those retired routes used to reach AXe, idevice or ipb helpers. The CLI no longer contains them (see [retired helpers](dependencies.md#retired-helpers)), and the execution policy would refuse those binaries anyway.

User-facing live mirroring, reusable semantic element handles, noticing a permission or Face ID prompt without being told to watch for it, crash recovery, device-side release after an uncertain one and a complete assertion system are missing or incomplete.

## How to read progress

Use three separate questions: is there an executable route, has that route been checked on this hardware, and does it recover from interruption/failure? A feature can answer yes to the first two and still be unsuitable for unattended use. No percentage is assigned, because counting commands would hide differences in scope and evidence.
