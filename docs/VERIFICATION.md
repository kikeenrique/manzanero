# Verification records

## MCP shutdown drains owned tool operations — 2026-11-13

Added a project-owned operation registry around MCP tool handlers. The pinned SDK 0.12.1 stops its reader/transport without cancelling/awaiting every tool handler, so SDK stop alone is insufficient for input cleanup. The registry admits a task before device work begins, forwards request-handler cancellation to it, and closes admissions before shutdown cancels and drains all owned tasks. SDK stop resolves outstanding host elicitation continuations before draining to avoid a shutdown deadlock. CommandService checks cancellation on entry so a cancelled queued command does not begin device work. A closed embedded session rejects restart; another transport needs a new session.

The stdio runtime runs this shutdown on stdin EOF and on SIGINT/SIGTERM. EOF normally exits 0 and has a 30-second cleanup watchdog (expiry exits 1). Signals use the process cancellation scope and exit 130/143 after cleanup, with the existing repeated-signal/deadline force-exit behavior. Embedded session stop/wait methods drain without terminating their host process. No dependency or helper executable was added. The registry owns operation tasks only; it does not establish exclusive device ownership across processes.

All 200 local Swift test functions passed with zero warnings/errors. New checks cover cancellation and delayed cleanup of one/three concurrent owned operations, shutdown admission rejection/idempotence, parent-to-owned-task cancellation, stopping a session with a pending elicitation request, closed-session restart rejection and EOF deadline arming/disarming. Existing shared CLI/MCP and handoff checks still pass. Build passed; all 29 mise tasks validate.

Opt-in stdio checks on the awake/unlocked USB iPhone 13 mini submitted a nine-second Maps-icon hold, waited two seconds, and stopped only the owned MCP process. EOF exited normally with 0 after 2.242 seconds; SIGTERM exited normally with 143 after 2.139 seconds. An interrupted tool observation also left a completed SIGINT artifact at 2.050 seconds; process inspection confirmed no test/server remained active. A separately observed final SIGINT test passed with exit 130 after 2.255 seconds, zero pending output bytes and no force-exit diagnostic. The observed EOF/SIGTERM tests also checked absence of pending ordinary responses and non-use of force exit. Separate screenshots were captured after each process ended; they are private artifacts under ignored `tmp/`, and no UI-effect or device-side release assertion is inferred from process exit.

These results establish scoped early host-process shutdown during input, not exact contact delivery/release, crash cleanup or every tool's cancellation behavior. Forced exit/deadline expiry has local injected coverage, not live-device proof. SIGKILL, crashes, broken output with stdin still open, disconnection recovery, stalled Apple APIs/tools, partial text/clipboard/file changes, cross-process ownership and quarantine remain limitations. This does not complete unattended testing or full feature parity.
